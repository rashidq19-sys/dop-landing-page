## Method and its limits (read this before trusting the numbers)

The DataForSEO-backed tooling this report is meant to use **is not installed**:

| Expected tool | State |
|---|---|
| `~/.claude/skills/seo/scripts/domain_overview.py` | Missing — directory does not exist |
| `bdata` (Bright Data CLI) | Not on PATH |
| DataForSEO credentials | No env vars, not in `.env`, no MCP server |

The `seo-keywords` / `seo-technical` / `seo-content` agents were **not** run: their first step is
to execute that missing script, so they would have failed or improvised untraceable numbers.

Rankings below therefore come from **live web search**, which carries two limits that matter:

1. It returns a **result set, not a de-personalised, geo-fixed UK SERP**. Positions are recorded as
   *appears / does not appear*, never as a bare rank integer.
2. The search backend is **US-biased** and **ignored the `site:` operator** (a `site:dspops.app`
   query returned unrelated domains rather than zero results). So "does not appear" here means
   *did not surface in these checks* — it is **not** proof of de-indexing. Google Search Console is
   the only authority on index status, and this run has no access to it.

Technical checks (Section 2) used raw `curl` against live production and **are** reliable.

## 2. Indexing and technical spot-check — all clean

Every URL in `sitemap.xml` was fetched from live production and checked for status, a
page-specific `<title>`, and a **self-referencing canonical**. Status code alone is not the test
here: this repo's prerenderer exits 0 even when it fails, which ships a sub-page as the SPA shell —
HTTP 200 but carrying home's title and `canonical = /`. That is the exact soft-404 signature Google
rejected before, so canonical agreement is the real check.

**Result: 25 / 25 URLs clean. No soft-404 regression.**

| Route | HTTP | Title | Canonical |
|---|---|---|---|
| `/` | 200 | DSPOps — Amazon DSP Management Platform for UK Delivery Service Partners | self ✓ |
| `/amazon-dsp-management-software` | 200 | Amazon DSP Management Software UK \| DSPOps | self ✓ |
| `/dsp-rota-management` | 200 | DSP Rota Management Software \| DSPOps | self ✓ |
| `/van-inspection-app` | 200 | Van Inspection App for Amazon DSP Fleets \| DSPOps | self ✓ |
| `/blog` | 200 | DSPOps Blog — Practical guides for UK Amazon DSPs | self ✓ |
| + 20 more (feature pages, 15 blog posts, `/privacy`) | 200 | page-specific | self ✓ |

Home and the pillar page still carry **different** titles and descriptions — the duplicate-canonical
demotion documented in the repo lessons has not regressed.

Other checks:

- `sitemap.xml` — 200, `application/xml`, 25 URLs, all resolving.
- `robots.txt` — 200, correct. Allows all, disallows `/admin`, `/download`, `/api/`, and both
  `noindex` sales brochures. Sitemap declared.
- **Junk URL returns a real 404** (not a 200 soft-404). The catch-all allowlist fix is holding.
- **No accidental `noindex`** on any public page.
- **Structured data present** — 4 JSON-LD blocks on each key page, 3 on `/blog`.
- **Speed is excellent** — TTFB ~35-40ms from the London edge (`lhr1`); gzip active, cutting the
  homepage from 500 KB to 124 KB on the wire.

Nothing in the technical layer is holding this site back. **The problem is authority and
discovery, not the build.**

## 3. Top 3 opportunities

### 1. Fix the brand term first — `dspops` returns nothing

The site does not surface for its own name, which is the cheapest and most damaging gap on this
list. Someone handed the name in a sales call cannot find the product. Every non-brand ranking
ambition is downstream of this.

This is almost certainly a **domain authority and citation problem, not a technical one** — the
crawl surface is clean. The fastest levers, roughly in order:

- Confirm actual index status in **Google Search Console** (the one thing this run could not do)
  and request indexing for anything missing.
- Build foundational citations that carry the exact brand string: **Companies House, a LinkedIn
  company page, Crunchbase**.
- **Get listed on the software directories the competitors already occupy** — GetApp UK,
  SoftwareAdvice GB, G2, Capterra. These surfaced repeatedly in the searches above and are the
  single clearest route into this SERP.

### 2. Stop competing for "DSP management software" — the term means advertising

The searches make this unambiguous: `dsp management software` and `amazon dsp management software uk`
return **demand-side platform ad-tech** (Extron audio DSP, Amazon Ads, agencies like Lezzat and
WAKE). `dsp rota management` returns **USPTO signal-processing patents**. These are not near-misses;
the head terms belong to different industries, and traffic won on them would largely be wrong-intent.

Notice what the sites that *do* rank in the delivery sense have in common — LMDmax, Courio, Zerity
all spell out **"Delivery Service Partner"** rather than leaning on the bare acronym. Recommend
shifting emphasis toward unambiguous long-tail:

- "Amazon Delivery Service Partner software UK"
- "DSP driver rota software" / "delivery driver rota software UK"
- "Amazon DSP fleet management UK"

Keep the existing exact-match pages — they cost nothing and the pillar is correctly canonicalised —
but treat them as long-game, not as the near-term traffic source.

### 3. `/van-inspection-app` is the most winnable non-brand page — press it

The `van inspection app` SERP is entirely **generic fleet tools** (Fulcrum, Track-POD, SafetyCulture,
Simply Fleet). Not one result is Amazon-DSP-specific, and none is UK-specific. DSPOps already has a
dedicated, well-formed page aimed exactly at that gap.

This is a genuine niche opening rather than a head-on fight. Worth strengthening with comparison
content ("van inspection app for Amazon DSP fleets vs generic fleet apps"), UK/DVSA compliance
angles, and internal links from the blog's existing van-damage and inspection-compliance posts.
